# boat-helm-display

Smart-knob **display driver** for the Anders 11807 / Levetop **LT168A** 1.3" round
rotary-encoder LCD — the boat helm "brain" display.

Instead of hard-coding one screen per instrument, the flashed image is **one generic
canvas of addressable slots**, and the host composes *any* instrument at runtime over
UART — no reflash. RPM, temperature, fuel and autopilot are just **data** in an
instrument registry.

![instruments](docs/instruments.png)

## How it works

The LT168A is a *smart display*: it renders a GUI from its own flash (authored in
UI_Editor-II on Windows), and the host drives widgets by writing values to addresses
over a `5A A5`-framed serial protocol. So this repo is two halves:

- **The canvas** (`build/`, generated by `tools/gen_canvas.py`) — a 240×240 page with
  a 60-tick ring (each tick an addressable Icon, 12 colours), a colour/gradient ring
  backdrop, a top reference triangle, a mode-label slot, a symbol slot and a 4-digit
  value. One "canvas compiler" script emits every asset **and** the page `.cfg`.
- **The driver** (`tools/instrumentctl/`, Go) — an instrument **registry**. Each
  instrument is `{mode, symbol, ring, min/max, value-zones, sweep, style}`; the driver
  colours the ticks (bright fill up to the reading, dim of the zone colour to max) and
  sets the slots. `styleFill` = gauge, `stylePointer`/autopilot = compass.

## Layout

| path | what |
|------|------|
| `tools/gen_canvas.py` | canvas compiler — assets + `build/Plugin/Page0000.cfg` + `boat-helm.uiprj` |
| `tools/instrumentctl/` | Go host driver (static binary, no deps) — `-instrument`, `-autopilot`, … |
| `build/` | the UI_Editor-II project (compile on Windows, flash with LT_VCom) |
| `CLAUDE.md` | full project context, hardware/protocol notes, hard-won gotchas |
| `BUILD.md` | compile → flash → drive checklist + canvas address map |

## Quick start

```bash
# regenerate the canvas (assets + cfg)
python3 -m pip install pyserial pillow
python3 tools/gen_canvas.py

# compile build/boat-helm.uiprj in UI_Editor-II (Windows) → flash with LT_VCom

# drive it from Mac/Pi over the CN2 UART (3.3V USB-TTL adapter — NOT USB-C)
cd tools/instrumentctl && go build -o instrumentctl .
./instrumentctl -instrument rpm  -value 2600 -port /dev/cu.usbserial-XXXX
./instrumentctl -instrument temp -value 75
./instrumentctl -instrument fuel
./instrumentctl -autopilot cog -heading 120 -current 90
```

## Hardware notes

- **Runtime commands go over CN2 UART, not USB-C.** USB-C is power + flashing only.
  Wire a 3.3 V USB-TTL adapter: TXD→CN2 pin5(RX), RXD→CN2 pin4(TX), GND→CN2 pin7. 115200.
- Compiling/flashing needs the Windows-only UI_Editor-II + LT_VCom. See BUILD.md.
