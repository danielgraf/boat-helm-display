# Boat Helm Display — Project Context

A rotary knob display for a boat helm ("boat brain" project). This file orients any
new session on hardware, protocol, conventions, and current state.

## Hardware

- **Module:** Anders 11807 — 1.3" IP65 rotary encoder LCD. Levetop **LT168A** MCU, 16MB flash,
  USB/UART interface, GC9A01 panel, 240×240 round, encoder + pushbutton.
- **Model family:** RT-TFT-Φ49-305.
- **Architecture:** SMART DISPLAY. The LT168A renders a GUI (authored in UI_Editor-II, a
  Windows tool) from its own flash; the host drives it with a serial command protocol.
  You CANNOT run your own LVGL/framebuffer on it or reach the GC9A01 directly — the panel
  is behind the LT168A. Direct-render LVGL would require a *bare* GC9A01 module instead.
- **Connection:** USB-C to host → enumerates as USB-CDC serial (`/dev/cu.usbmodem*` on macOS).
  NOTE: app note shows host UART on CN2 TX/RX pins via a separate USB-TTL adapter; confirm
  whether the command protocol comes out over USB-CDC or only CN2. Bench script settles it.

## Serial protocol (verified against datasheet + UI_Editor's own command export)

- Frame: `5A A5 | Length | Cmd | Addr(2) | Data(2·n) | CRC(2)`
- Length = bytes after Length = Cmd(1)+Addr(2)+Data(2n)+CRC(2)
- Cmd: `0x10` write, `0x03` read, `0x41` touch/return
- CRC: **CRC-16/MODBUS** (poly 0xA001 reflected / 0x8005), over Cmd+Addr+Data only
  (NOT header, NOT length), emitted **little-endian** (low byte first).
  Verified against two datasheet examples (BC43, 4C30) AND UI_Editor's SerialPortCommands.csv.
- Config from boat-helm.ini: StartByte 5A A5, Modbus 0, NoCRC 0 (CRC on), NoFeedBack 0
  (module ACKs), aRGB_Png 1 (alpha PNG icons supported), 240×240, StartPage 0.
- Baudrate: ini says index `4` — CONFIRM what rate index 4 maps to before first serial session
  (likely 115200; try 9600 as fallback).

### System registers (confirmed from Anders app note + SerialPortCommands.csv)
- `0x7000` page switch  | `0x7001` brightness (0–63) | `0x700E` auto-dim | `0x700F` dimming
- `0x7010` sleep delay  | `0x7002-0x7008` RTC/date-time | `0x703F` multi-language
- `0x1FF1` LED ring colour (bitfield: 0 off,1 blue,2 green,4 red) | `0x1FF2/3` LED min/max | `0x1FF4` step

## Project conventions (from the existing boat-helm-build)

- **Pages (5):** 0=rpm, 1=temp, 2=fuel, 3=course, 4=autopilot. Backgrounds in Picture/.
- **Asset numbering:** 4-digit IDs, `NNNN` or `NNNN_comment`.
  - `01[page][n]` — per-page backgrounds/icons (0100 rpm, 0110 temp, 0120 fuel, 0130 course, 0140 autopilot)
  - `02xx` — shared digit sets (0200-0209 = 36px digits, 0220-0229 = 22px digits) for pngNumber widgets
  - `03xx` — shared gauge CHROME (rings/ticks/triangles) — added this session
- **Widget write-addresses:** `0x00[page+1][slot]` — page0 needle 0x0011, page1 0x0021,
  page2 0x0031, page3 0x0041 + pngNumber 0x0042, page4 needles 0x0051/0x0053 + numbers 0x0052/0x0054.
- **Chrome write-addresses (this session, shared, no overlap with above):**
  minor-tick "on" 0x0320–0x0337 | major-tick "norm" 0x0340–0x034B | triangle "act" 0x0350–0x0353.

### Asset folder rules (UI_Editor-II)
- `Picture/` — page backgrounds, **BMP or JPG only (NOT PNG)**, opaque.
- `Icon/` — icons, digits, ticks, rings, triangles — **BMP/JPG/PNG**, PNG alpha OK.
- `Needle/` — AUTO-GENERATED by the Needle widget; do not add art. Needles are VECTOR
  (NDLDType:0), drawn by widget params, not baked PNGs.
- Names: no `\ / : * ? " < > | . ,` ; only one dot (extension separator).
- Same-group icons must share width/height (all chrome is full 240×240 → uniform, safe).
- Uncalled assets aren't compiled into UartTFT-II_Flash.bin (except audio).

## Gauge geometry (matches the 03xx chrome assets)

- 270° sweep, dark-marine palette (black bg; white/cyan; amber warn; red alarm).
- Shared centre (120,120). All assets full-frame 240×240, transparent, registered to that centre.
- Needle: **0°=due south**, clockwise. For the 270° gauge → **startAngle=45, finalAngle=315**,
  leaving a 90° gap centred on south (bottom). defaultValue must be in [45,315].
- 24 minor ticks + 12 major ticks + 4 edge triangles. Rings outer(white)/inner(cyan).

## CURRENT DIRECTION: generic TICK CANVAS (composed at runtime) — supersedes the needle

Goal (from the user): a **multi-use framework** — bake ONE generic canvas of addressable
slots, and have the host compose ANY instrument at runtime (RPM, autopilot, depth, …) with
no reflash. NOT knobstudio's fixed pre-defined screens.

Why we left the needle: a swept vector needle repaints its whole bounding box every update,
single-buffered → the panel visibly FLICKERS on a fast sweep. No host double-buffering
exists (smart display owns rendering). The fix is a different primitive: a **ring of
individually-addressable ticks** — each tick is a tiny Icon redraw, so only the ticks that
change are touched → flicker-free. Center stays clear for a value + icon; works full-circle
(autopilot heading) with no bottom-gap special-casing.

Hardware capability facts (verified from the UI_Editor manual §9/§10):
- **No runtime draw primitives** (no draw-line/rect/pixel). Platform is purely widget-based.
  So "any screen programmatically" = compose the CONTENT of pre-placed slots, not paint pixels.
- BUT content is fully dynamic over UART, no reflash: **write arbitrary strings to String_Label**
  (§9 "Write String Data to Variable Address"), **switch which image an Icon shows by index**
  (§10 "Write Command to Switch Icon"), set numbers, drive gauges, LED ring.
- Ceiling: slot POSITIONS, the font, and the icon library are baked (reflash to change those).

### The canvas (generated by tools/gen_canvas.py → assets + Plugin/Page0000.cfg)
One "canvas compiler" script emits every asset AND the cfg. Slots + write-addresses:

| slot | addr | indices / value |
|------|------|-----------------|
| 60 ticks (360°) | `0x0100`..`0x013B` | 0 off · 1 grey · 2 white · 3 green · 4 yellow · 5 red |
| top triangle (lubber) | `0x0140` | 0 off · 1 white · 2 green · 3 red |
| mode label | `0x0141` | 0 RPM · 1 COG HOLD · 2 TWA HOLD · 3 AP HOLD · 4 OFF |
| symbol slot (12 o'clock) | `0x0142` | 0 gauge · 1 autopilot · 2 wind |
| value | `0x0150` | 4-digit 0..9999 (digits 0200–0209) |
| LED ring / brightness | `0x1FF1` / `0x7001` | system regs |

Tick images 0500–0505 (shared by all 60 ticks), triangle 0510–0513, mode 0520–0524,
symbol 0530–0532. Background `Picture/0100_canvas.png` is BLACK so opaque RGB565 tick
sprites composite seamlessly. Full map in `build/canvas_map.csv`.

**Icon widget cfg format** (decoded from the Anders Shower demo — canonical):
`icon_NAME:parAddr,2,writeAddr,2,X,Y,W,H,firstImg,lastImg,RGB565,,defaultIdx,1,NAME,Disable,0xFFFF,1`
An Icon holds a contiguous image range (firstImg..lastImg); write an index to pick one.
Shower compiled 310 icons fine, so the shared-tick approach (~25 icons) has huge headroom.

Driver: `tools/instrumentctl` (Go, static binary — no pyserial). `-rpm` composes the RPM
instrument on the canvas and runs a gentle rev; ticks are change-gated → flicker-free.

## (superseded) iteration 1 — single vector-needle gauge — HARDWARE FACTS STILL VALID

Built, flashed, and confirmed on the real Anders knob (photo 2026-08-01): neutral dial +
vector needle + numeric readout render and drive by address. Replaced by the tick canvas
above (needle flickers), but the compile/hardware learnings below remain true.

Hard-won facts from getting it to compile+run (do NOT relearn these):
- **needleType must be `2D`** (vector line needle, drawn from W/L1/C1/L2/C2 params) — NOT
  `2Dsmooth`, which is image-based and needs baked frames in Needle/ that only the editor
  generates ("firstImage/lastImage missing" if hand-authored).
- **"needle_0: more than Max value" is a NON-FATAL warning.** It appears (relates to the
  wide 45–315 sweep / a byte-ish angle cap) but the bin still builds and the needle renders
  and positions correctly on hardware. Don't block on it.
- **pngNumber for an INTEGER readout needs `decimalDigit = 0`.** With decimalDigit=1 it
  stores tenths and needs a decimal-point glyph absent from the 0–9 digit set → renders
  blank. integerDigit=3, decimalDigit=0, firstIcon 0200_digit36, lastIcon 0209_digit36.
- **The UI_Emulator does NOT persist a written pngNumber value across its repaint** (the
  number flashes then vanishes in the emulator). On hardware it holds — verify on device,
  not the emulator, for value persistence.
- Editor edits happen in its in-memory model; hand-edited .cfg only takes effect after
  File→Open reloads the project. Keep cfg and editor in sync or edit in one place.

## DIRECTION CHANGE — generic gauge canvas (iteration 1)

Pivoted away from 5 hardcoded instrument pages toward ONE reusable, host-driven gauge.
The flashed image is a single page; the host makes it any instrument at runtime by
driving the needle + numeric readout + LED ring over serial. Full checklist in BUILD.md.

Generic Page 0 widgets (Plugin/Page0000.cfg):
- `needle_0`    @ 0x0011  — vector needle, sweep 45..315 (0°=south CW), default 180.
- `pngNumber_0` @ 0x0012  — 3-digit 36px readout, 0..999, digits 0200–0209.
- LED ring @ 0x1FF1 · brightness @ 0x7001 (system regs, generic — no widget needed).
Driver: `tools/instrument.py` (maps value→angle, drives needle+number+ring; verified
frames match SerialPortCommands.csv byte-for-byte).

### Notes correcting earlier assumptions (verified against a real 21:14 compile log)
- **Plugin/*.cfg are plain UTF-8-with-BOM TEXT, not binary.** One comma-separated record
  per widget. Layout/addresses/position ARE hand-editable and drive correctly (needle
  angle writes verified in the UI_Emulator, frames byte-match SerialPortCommands.csv).
- **Icon ID = the 4-digit number in the filename.** `0200_digit36.png` → icon 200.
  The compiler walks 0..maxID and prints a harmless "icon N does not exist" for every gap
  in that sparse space — NOT an error. Real errors go only to Make_error_info.txt.
- **pngNumber compiles once its digit images are in Icon/** (digits 0200–0209 = icons
  200–209). It was misfiled in Picture/ before; now fixed. Blank readout in the emulator
  was just the pre-compile state.
- **BUT: hand-authoring cfg is NOT sufficient for widgets that need generated companion
  assets.** The "2Dsmooth" needle is IMAGE-based: UI_Editor pre-renders a rotated needle
  frame per angle into the `Needle/` folder at build time. Hand-editing the cfg can't
  create those, so the bin compiler fails with "the needle's firstImage or lastImage is
  missing" / "more than Max value" even though the emulator draws it vectorially.
  → Needle widgets must be (re)created through the UI_Editor-II GUI so it generates
  `Needle/` art. Drive is still fully scriptable afterwards (write angle to 0x0011);
  only the build-time needle asset needs the editor once.
- Instrument-specific backgrounds/pages (rpm/temp/…) are set aside; Pages 1–4 blanked,
  uiprj lists only Page 0. The neutral dial is `Picture/0100_gauge.png` (baked from chrome).

## Runtime drive path (confirmed on hardware)
USB-C = power + FLASH only. Runtime commands go over **CN2 UART** via a 3.3 V USB-TTL
adapter (CP2102), crossed: adapter **TXD→CN2 pin5 (RX)**, adapter **RXD→CN2 pin4 (TX)**,
adapter **GND→CN2 pin7 (GND)**. CN2 = A2501H-7P (1:5V, 2:D-, 3:D+, 4:TX, 5:RX, 6:BUSY, 7:GND).
Port on Mac: `/dev/cu.usbserial-*` @ 115200.
